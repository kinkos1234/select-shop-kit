# 아키텍처

## 3층 구조
```
[입출력]   Discord / Claude Code CLI  ← 자연어 한 줄, 녹음 파일, CSV
[실행]     Claude Code + 스킬 4종     ← 파싱·검증·집계 (append-only 원장 규율)
[데이터]   Notion DB 13종             ← 단일 진실원, 사람이 보는 화면
```

## DB 13종과 관계
- **브랜드** ← 스타일(드롭) ← **상품(SKU)** — 마스터 3단
- **발주(PO)** ← 재고이동(사입입고) : 입고액 자동 대사, 미입고 잔액
- **재고이동**(비판매 이동 원장) + **매출 대장**(판매 라인 원장) → 상품 현재고 = 입고합 − 판매합
- **주문(자사몰)** 헤더 ← 매출 라인 : 라인합계 ≠ 상품합계면 누락 감지
- **고객** ← 주문 : 구매횟수·누적구매액 rollup
- **정산** : PG/카드 수수료·실입금 대사 (차이금액 formula)
- **거래처** : 미지급금 = 미지급 사입 이동 합계 (수동 입력 금지)
- **일정 / 회의록** : /meeting 이 녹음 → 회의록 + 액션아이템 자동 연결

## 원장 규율 (중요)
1. **append-only** — 기존 행 수정 금지, 정정도 새 행
2. **원가 스냅샷** — 판매 시점 사입가를 행에 복사 (재사입 가격 변동이 과거 마진을 소급 변경하지 않음)
3. **멱등키** — Discord 메시지 ID / CSV 해시+행번호. 같은 입력 재처리 시 자동 스킵
4. **교환 = 2행** (반품 행 + 판매 행), 반품 = 음수 행
5. **재고 직접 수정 금지** — 실사 차이도 "실사조정" 이동 행으로

## 한계 (알고 쓰기)
- Notion API는 초당 ~3요청 — 월 수백 건 규모까지가 적정선
- 월 주문 300건+ / 반품 월 10건+ / 월말 정산 2시간+ 이면 SQLite/Postgres 원장 + Notion 뷰 구조로 이전을 검토
- Notion 은 트랜잭션·유니크 제약이 없다 — 멱등키가 이를 보완하지만 동시 쓰기 주체를 늘리지 말 것
