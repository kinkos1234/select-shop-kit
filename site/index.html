Architecture

3층이면 충분합니다

POS도, ERP도, 서버도 없습니다. 이미 쓰는 도구 3개를 원장 규율로 묶습니다.

입출력

Discord

매장에서 폰으로 한 줄 입력. 녹음 파일, 주문 CSV도 여기로 던집니다. 직원 3인이 같은 채널을 씁니다.

실행

Claude Code

자연어를 파싱해 상품을 매칭하고, 검증하고, 기록합니다. 스킬 4종이 워크플로우를 강제합니다.

데이터

Notion

DB 13종이 단일 진실원. 사람은 대시보드·갤러리·칸반으로 봅니다. 셋업 스크립트가 전부 자동 생성.

Workflows

실제로 이런 일이 자동화됩니다

판매 한 줄
상품 매칭 → 매출 행 + 원가 스냅샷 + 재고 차감. 반품은 음수 행, 교환은 반품+판매 2행 — 과거 기록은 절대 수정하지 않습니다.
회의 녹음 업로드
로컬 whisper로 전사(녹음이 외부 서버로 안 나감) → 요약·결정사항·액션아이템 → Notion 회의록 + 일정 DB 자동 등록.
자사몰 주문 CSV
플랫폼 무관 컬럼 자동 인식 → 주문 헤더/라인 분리 기록. 멱등키(파일 해시+행번호)로 같은 파일을 두 번 올려도 이중 기록 없음.
발주 → 입고
발주(PO)에 입고 기록이 자동 대사 — 미입고 잔액이 실시간 계산. 해외 브랜드 부분입고 추적.
"마감하자"
오늘 매출 요약 + 미기록 확인 질문 + 내일 일정 브리핑. 월간 리포트는 채널·브랜드별 순매출, 드롭 sell-through, 부가세 예상액까지.

Ledger Discipline

템플릿이 아니라 규율입니다

예쁜 장부는 많습니다. 이 킷의 가치는 숫자가 틀어지는 경로를 코드로 막는 데 있습니다.

  • Append-only 원장기존 행 수정 금지. 정정·반품·교환 전부 새 행 — 숫자의 근거가 사라지지 않습니다.
  • 원가 스냅샷판매 시점 사입가를 행에 복사. 다음 시즌 재사입으로 사입가가 올라도 지난달 마진이 바뀌지 않습니다.
  • 멱등키Discord 메시지 ID·CSV 해시가 키. 재전송·재업로드에도 이중 기록이 생기지 않습니다.
  • 자동 대사발주↔입고, 주문 헤더↔라인 합계, 정산 실입금↔장부 — 어긋나는 순간 formula가 드러냅니다.
  • 재고 직접 수정 금지실사에서 1개가 비면? 수량을 고치는 게 아니라 "실사조정 −1" 행을 남깁니다.
Get Started

10분 설치

# 1. 클론 git clone https://github.com/kinkos1234/select-shop-kit && cd select-shop-kit # 2. Notion Integration 토큰 발급 (notion.so/my-integrations) 후 허브 페이지에 연결 export NOTION_TOKEN=ntn_xxx # 3. DB 13종 + 뷰 + 대시보드 자동 생성 python3 setup/create_databases.py <parent_page_id> --staff "대표,직원A,직원B" # 4. Claude Code 스킬 설치 ./install.sh
정직한 한계 — Notion을 원장으로 쓰는 구조라 월 수백 건 규모까지가 적정선입니다. 월 주문 300건+, 반품 월 10건+, 월말 대사 2시간+ 이면 전용 DB 이전을 검토하세요. 판단 기준은 저장소의 architecture.md에 있습니다.
